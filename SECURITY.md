# Seguridad y datos clínicos

Este repositorio no acepta cursos clínicos reales, identificadores, claves ni
capturas de sistemas asistenciales en incidencias, commits o pull requests.

Para comunicar una vulnerabilidad, utiliza un canal privado del propietario del
repositorio. No abras una incidencia pública con detalles explotables o datos de
pacientes.

Antes de cualquier piloto hospitalario se requiere, como mínimo, autorización
institucional, evaluación de protección de datos, control de acceso, registro de
auditoría, gestión externa de secretos, validación local bloqueada, supervisión
humana y un procedimiento de parada y rollback.

El software es docente y no es un producto sanitario ni debe generar decisiones
clínicas autónomas.
